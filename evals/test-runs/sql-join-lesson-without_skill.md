Отлично, начинаем! `SELECT * FROM table` — это уже хорошая база: JOIN — это тот же SELECT, просто данные берутся сразу из нескольких таблиц.

## Урок 1. Зачем нужен JOIN и как работает INNER JOIN

### Проблема

Представь интернет-магазин. Данные в базе обычно хранят **раздельно**, чтобы не дублировать их:

**Таблица `customers` (клиенты)**

| id | name  | city    |
|----|-------|---------|
| 1  | Анна  | Москва  |
| 2  | Борис | Казань  |
| 3  | Вера  | Пермь   |

**Таблица `orders` (заказы)**

| id  | customer_id | amount |
|-----|-------------|--------|
| 101 | 1           | 500    |
| 102 | 1           | 1200   |
| 103 | 2           | 300    |
| 104 | 5           | 800    |

Обрати внимание: в `orders` нет имени клиента — только `customer_id`, то есть **ссылка** на `id` из таблицы `customers`. Это и есть связь между таблицами.

Вопрос бизнеса: *«Покажи имя клиента рядом с каждым его заказом»*. Одним `SELECT * FROM orders` не обойтись — имён там нет. Тут и нужен JOIN.

### Синтаксис

```sql
SELECT customers.name, orders.amount
FROM orders
JOIN customers ON orders.customer_id = customers.id;
```

Разберём по частям:

- `FROM orders` — начинаем с таблицы заказов (как ты уже привык).
- `JOIN customers` — «приклей к ней таблицу клиентов».
- `ON orders.customer_id = customers.id` — **правило склейки**: строка заказа соединяется со строкой клиента, если `customer_id` заказа равен `id` клиента.
- `customers.name` — пишем `таблица.столбец`, чтобы было понятно, откуда берём столбец (в обеих таблицах есть `id`, и без префикса база запутается).

`JOIN` без уточнений = `INNER JOIN`, это одно и то же.

### Как это работает «в голове»

База берёт каждую строку из `orders` и ищет в `customers` строку с подходящим `id`:

- заказ 101, `customer_id = 1` → нашёлся клиент 1 (Анна) → строка попадает в результат
- заказ 102, `customer_id = 1` → снова Анна
- заказ 103, `customer_id = 2` → Борис
- заказ 104, `customer_id = 5` → клиента с `id = 5` **нет** → строка **не попадает** в результат

Результат:

| name  | amount |
|-------|--------|
| Анна  | 500    |
| Анна  | 1200   |
| Борис | 300    |

Главное правило INNER JOIN: **в результат попадают только те строки, для которых нашлась пара в обеих таблицах.** Всё, у чего пары нет, отбрасывается.

### Небольшое удобство: псевдонимы

Чтобы не писать длинные имена таблиц, им дают короткие псевдонимы:

```sql
SELECT c.name, o.amount
FROM orders o
JOIN customers c ON o.customer_id = c.id;
```

Это ровно тот же запрос, просто короче.
