# Как участвовать

Правки принимаются через pull request в `main`. Людям и агентам правила одни.

## Что можно предложить

- **Новый предмет.** Скопируйте `domains/_template.md` в `domains/<предмет>.md`, заполните и добавьте строку в таблицу маршрутизации в `SKILL.md`.
- **Новая методика в модуле.** Формат памятки: суть, когда применять, граница, эффект. Эффект указывайте из мета-анализа или контролируемого исследования (g/d) со ссылкой в описании PR. Методики без отложенного теста не добавляем.
- **Правка ядра** (`SKILL.md`, раздел «Неизменная основа»). Только с обоснованием: какой сбой она чинит и где он виден (лог симуляции, живой тест).
- **Новый сценарий симуляции** в `evals/sim-tests/scenarios.py`.

## Перед pull request

1. Поднимите `version` в `plugins/evidence-based-tutor/.claude-plugin/plugin.json`, если меняется поведение скилла (semver: правка текста — patch, новый модуль или предмет — minor).
2. Проверьте, что `python3 -m py_compile` проходит по скриптам и `tools/build.sh` собирает архивы. То же делает CI.
3. Если правка меняет поведение тьютора, приложите прогон симуляции на затронутых сценариях: оценку судьи до и после.
4. Не коммитьте zip-архивы, `learner-state.json`, `learner-profile.md` и личные данные учеников.

## Живой тест

Пока идёт живой тест, вопросы проверок и ключи ответов (`evals/live-test/tests/`, `evals/live-test/keys/`) в репозиторий не попадают: тестируемый не должен их видеть. Они хранятся приватно у проводящего тест и добавляются после 30-го дня.

## Релиз

Создайте релиз на GitHub (Releases → Draft a new release, новый тег `vX.Y.Z` на `main`) или запушьте такой тег. CI соберёт оба архива и прикрепит их к релизу.
